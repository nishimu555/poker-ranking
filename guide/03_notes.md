# 注意点

## 1. AI が書き換えない欄・ファイル

次は開発者が書く場所です。AI は読むだけで変更しません。

| 対象 | 内容 |
|---|---|
| `docs/a0_request/`、`docs/_reference/` | 依頼書、参考資料 |
| plan の「開発者回答：」 | 質問への回答 |
| plan の dev 項目・review 項目の本文 | 開発者からの質問・指示、レビュー指摘 |
| plan の「1. 進捗」の「6. 成果物レビュー」 | ☑ は開発者だけが付ける（成果物が変わると、AI が ☑ を外して再レビューを依頼する） |
| `docs/c4_test/test-report.md` の開発者の結果欄 | 開発者が実行したテストの結果 |
| `docs/d1_setup/setup-guide.md` の開発者の検証結果欄 | 開発者が試した手順の結果 |

逆に、開発者は次を変更しないでください。

| 対象 | 理由 |
|---|---|
| plan の ☑（「成果物レビュー」以外） | AI の確認結果を示すため |
| `plans/_log/prompt-log.md` | 監査用の自動記録のため |
| `docs/b1_design/decisions/` の既存の記録 | 設計判断の経緯を残すため（判断を変える場合は dev・review 項目で指示し、新しい記録を作らせる） |

## 2. Claude Code の使い方の注意

- **組み込みのプランモードを正式な計画に使わない。** 組み込みのプランモードの計画はリポジトリの外に保存され、記録に残りません。正式な plan は必ず `plans/` に作られます。
- **スキルは開発者が実行する。** 各スキルは AI が自動で起動しない設定です。工程を進めるときは、必ずコマンドを入力してください。
- **工程を飛ばさない。** 前の工程が「完了」でないと、次の工程のコマンドは止まります。急ぐ場合でも、ゲートを外さず、質問に回答して進めてください。

## 3. コミット

- コミットは開発者が行います。AI は git コマンドを実行しません（コミット・プッシュのほか、`git status`・`git log`・`git diff` 等の確認も行いません）。
- 実装（c2）では、タスクごとに AI が示すコミットメッセージの案を使ってください（`[Task-001] 概要`）。コミットした後、c2 の plan の該当手順の実行結果に「コミット：<ID> <メッセージ>」を記入してください。AI はこの記入でコミットの有無を判断します。
- タスクとコミットを 1 対 1 にすると、再テストの対象の選定（c4）が正確になります。c4 は、c2 の plan と実装設計書の変更履歴から変更ファイルを特定します。
- plan や成果物の変更も、工程の区切りでコミットすることを推奨します。

## 4. 秘密情報

- 認証情報、API キー、パスワード等は、依頼書・plan・回答に書かないでください。ファイルに残り、Git の履歴にも残ります。
- 手順書には入手方法・保管場所・扱い方のみが書かれます。
- 認証情報のファイル（例：`clasp` の `.clasprc.json`）は `.gitignore` で Git の管理対象外にします。

## 5. 引き継ぎ・作業の再開

AI に作業を引き継がせる場合、または別の人が作業を再開する場合は、次の順で読みます（読む量を減らしてトークンを節約するため）。

1. `plans/README.md`（全工程の状況、次に行うこと）
2. 作業中の工程の plan ファイル
3. 必要な成果物のみ
4. コードは `docs/c2_implement/implementation-design.md` を読んでから、必要なファイルのみ
5. `plans/_log/prompt-log.md` は、経緯の確認が必要な場合のみ

## 6. 困ったとき

| 事象 | 確認すること |
|---|---|
| `/` の候補にコマンドが表示されない | `.claude/skills/<名前>/SKILL.md` が存在するか。Claude Code を再起動したか |
| `/a1-requirements` が始まらない | `request.md` のステータスが「確定」か |
| 次の工程が始まらない | `plans/README.md` で前の工程が「完了」か。差し戻し中の工程がないか |
| 「完了」にならない | 「成果物レビュー」に ☑ を付けたか。「9. レビュー指摘」に ☐ が残っていないか |
| `prompt-log.md` に記録されない | `settings.json` の `"disableAllHooks": true` を削除したか。`request.md` が存在するか。フックに実行権限があるか（`chmod +x .claude/hooks/*.sh`） |
| AI が質問ばかりして進まない | 資料に書かれていないことは質問するのが基盤のルールです。回答をまとめて書くか、`docs/_reference/` に資料を追加してください |
| AI の回答確認で ☑ が付かない | 「AI確認結果」に不足点が書かれています。枝番の追加質問（例：`Question-001-1`）に回答してください |

## 7. 基盤を変更する場合

- 基盤（`CLAUDE.md`、スキル、テンプレート）を変更する間は、フックを止めてください（`"disableAllHooks": true`）。
- 変更したら、本ガイドも合わせて更新してください。
- テンプレートに節を追加した場合は、対応するスキルの「確認観点」も追加してください（確認観点はテンプレートの節と対応させるルールです）。
